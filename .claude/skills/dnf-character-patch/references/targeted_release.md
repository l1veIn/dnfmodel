# 指定时装、武器及附加资源的打包工艺

适用于按装备外观生效的角色补丁、独立武器补丁，以及带技能特效和 Buff 的完整分享包。画面拆层见 [原生时装分层](costume_layers.md)，格式和编码细节见 [附加资产工艺](effects.md)。用 [验收清单](acceptance.md) 记录实际覆盖及校验结果。

## 按装备路径明确范围

1. 用试衣间、装备与图层索引、当前客户端 `sprite_*` NPK 做交叉盘点。记录职业、装备 ID、显示名、部位、内部 IMG 全路径、绘制顺序、源帧数及用途。不同装备共享同一路径时，它们会一起变化。遇到活动款、限时款、目录别名或过时的社区名称，用实际路径确认共享或独立的范围。
2. 为本体、武器、技能和 Buff 分别列出目标路径。雪人上衣、像素头、胖萌熊猫外观各自通过穿戴资源触发。战法变身或进化炫纹等分支另查实际引用，装备覆盖清单无法推导出这些分支。明确哪些资源属于普通攻击、变身和三觉条件，按普通形态与变身分别预览。
3. 从已核对的完整基包增量构建。肤色、部件、立绘、已有技能特效及其他继承资源只有在明确列入范围时才替换。对照基包以实际路径和载荷哈希确认目标内、目标外的差异。把复用载荷的别名写进范围，防止仅凭包名判断覆盖。

小咕嘎和 Doro 的雪人、像素头与胖萌熊猫沿用同一套目标触发逻辑，使用各自的外观像素。两套角色包有重叠资源，玩家按角色选择安装。Doro 的角色、技能、独立武器及 Buff 分别核对，装备命中、技能条件和视频触发各有自己的验证来源。

## 武器独立出包与载荷复用

- 借鉴社区包时，先离线列出其内部路径、图层用途、帧槽、空帧和载荷指纹，再与当前客户端资源交叉核对。此轮参考花篮的伴星与魔月之欲前后两层和原七夕花束对应载荷逐字节相同，因此可以把原先已经对好握点的一袋橘子映射过去。附件提供目标和结构参考，实际成品用项目已通过的素材。
- 先把袋提手或武器柄对准手的握点，在原生画布核对待机、走跑、快动作、武器掠过身体、背持和局部遮挡。复用到另一武器前核对动作帧表、前后层顺序，以及原武器是否另挂闪光、刀刃、柄头等副层。确认需要隐去时，生成保留预期帧位的透明 IMG。试衣间逐款核对内容和遮挡，武器与本体分装、合装各看关键帧。
- 用 `write_shared_npk` 让字节相同的 IMG 共享载荷，目录仍列出每个准确路径。一袋橘子 v02 的五款武器外观共有 17 个 IMG 目录项，前层 `c`、后层 `d` 和透明副层共用 3 份载荷。`c/d` 是这组武器的层位例子，换骨架或武器时重新核对绘制顺序、分层和帧槽。
- 本体 NPK 收角色、约定的觉醒和技能资源，武器另出可选 NPK。读取两个 NPK 的实际键清单，期望本体与武器的 IMG 路径集合没有交集。兼容提示按路径写，例如旧整合版、同一套角色或覆盖同一武器的花篮包需按说明选择其中一套。用两份包名分别说明安装与卸载。

## 技能特效按演出验收

- 先列出技能、条件、阶段、对应 IMG、ANI 或历史来源。把蓄力、聚合、接触和余波分开，留着原版节奏和触发关系。炫纹簇、星纹陨爆、湮灭黑洞和第六元素按各自表现改主体、果瓣或汁珠。普通形态、太古化身、进化炫纹、VP 和属性分支按实际映射检查，无法确认当前客户端触发的分支注明证据范围。
- 光效和实体分开决定。白闪和原有波形关系仍有用时，保留作为落点提示，在白闪回落后检查图案能否读出来。第六元素的切面在加亮光层叠合后会被洗白，先在完整叠层定位校正，再在现有合适的余波层上确认果瓣可读。加法混合的黑色占位在画面上可能无贡献，判空和验收须同时看 alpha 与混合结果。
- 用相同时间轴叠人物、武器、目标特效和其他原版层，比较原版与改版的前后切换、色亮、停留时长及首尾。用历史 ANI 或按素材重建时，在报告注明来源和演示时序。国服当前客户端的实际触发、间隔及 VP 分支分别留给实机记录。
- 格式转换（如 V5 改 V2）按源的帧数、零基索引、偏移、裁切、画布、链接目标及空槽约定回读。将最终解码的 alpha 和可见像素与将要发布的素材逐帧比对。武器换用经验证的其他层组，或技能因构图确需新偏移时，把容许差异列入目标清单以便回读。增量技能包合并后还要对完整人物包检查同名路径碰撞和继承载荷。

## Buff 成片与分享包回读

1. 记录用户本轮确认的工作台资产 ID、成片版本、源 manifest 和帧 SHA。通过登记条目找到编码报告及实际成片，逐项核对报告绑定的 manifest、源帧 SHA、成片 SHA 和编码参数。同名旧文件有自己的成片指纹，按实际身份选择。工作台有新版预览时仍须逐次指定它是否纳入本轮交付。
2. 通过客户端可用的映射逐个确认目标文件。女法这轮五个转职为 `battlemage`、`element`、`enchant`、`summoner` 和 `witch`，安装成员为 `Video/Character/Cutscene_buf/08_mage_F_buf_<转职>.bk2`。实际视频使用带透明通道的 Bink 1，以目标文件名 `.bk2` 分发。小咕嘎与 Doro 各自成片，五个同片别名的 SHA 应一致。源 PNG 及 Bink 解码预览都看开场、手势、停留和淡出，确认实际尺寸、帧数、帧率、透明度和音轨符合对应版本。其他项目按实际目标映射查询参数。
3. 明列 ZIP 成员与预期 SHA。本体、可选武器、五个新视频、使用说明和纳入的作者入口分别登记。继承上一版 ZIP 时先确认源 ZIP 指纹，替换名单写清具体成员，继承成员逐字节核对。说明中的文件名、升级方法和回退方式与这次出包对应。
4. 构建完成后打开**将要交付的 ZIP**。核对成员全集、重复路径、CRC 和每个安装成员的 SHA，比对需替换的每个 Buff 与本次确认成片。用 ZIP 取出的文件解码，若五个路径的 SHA 相同，可解码同内容的一份并对其他四项核 SHA。最后记录 ZIP SHA、组件版本和验证范围。

Doro 分享版 v1.4 继承了上一版的五个旧视频，虽然工作台已有新版双袋橘子预览。v1.5 定向更换五个 Buff，回读确认它们都匹配新版成片，本体 v08 与独立武器 v02 的载荷也通过校验。用 ZIP 内成员和确切成片比对才能发现这类漏装。

## 本轮替代的做法

| 历史做法 | 当前做法 |
|---|---|
| 把可选武器并进 Doro 角色 NPK | 角色与技能作为本体，武器另出一份并检查路径交集。 |
| 用文件名、装备名或某一处技能色直接推断覆盖范围 | 以装备与 IMG 映射、同资源别名、实际叠层及条件分支验收。 |
| 只看单层静态特效判断色彩与清晰度 | 用相同时间轴回看完整叠层，尤其核对最亮一拍之后。 |
| 从上一版分享包继承全部 `Video`，只检查 ZIP 能否打开 | 显式绑定本次成片，并从最终 ZIP 回读所有目标视频及继承组件。 |
