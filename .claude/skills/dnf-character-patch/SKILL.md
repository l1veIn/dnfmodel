# DNF 角色整体替换补丁

把一个职业的所有时装换成新角色的整体绘制精灵，保留原版动作和帧序号。范例是女枪手 Claude 大小姐 v02（用户评价“模范”）：配置 `design/claude_gunner/`，说明 `docs/claude_gunner_v02.md`。持武器、大附件、浅色服装的角色看女鬼剑 GPT 龙娘 v02：配置 `design/gpt_dragon_slayer_v02/`，说明 `docs/gpt_dragon_slayer_v02.md`。

## 不能越过的边界

- 只移动本项目的补丁文件（`A_*.NPK`），官方 `sprite_*` 包只读。
- 不启动游戏（有登录和反作弊），实机验证交给用户，汇报时写明未实机验证。安装前退出游戏，`install` 会检查。
- 不输出 65535 API key，不关闭用户的程序。
- 这些形象多是民间二创，作者和授权常无法核实。把来源和“仅自用”写进 `license_note`，并告诉用户。
- 付费调用：2.6 native 的 `16:9` 表约 $0.22 张，`3:2` 约 $0.29，`1:1` 约 $0.39，1k 的母版实测 $0.19–0.24。道具类用 `gpt-image-2` 约 $0.04（见 [references/effects.md](references/effects.md)）。提示词对了再画。花费前告诉用户估算，`cost` 看估算，账户余额差才是实际扣费（`s65535.py usage`，只读余额字段）。账户是共用的，别的会话也在生图时，余额差算不出单张费用，要如实说明，并在铺开前再读一次余额。

## 运行环境

```
PY=D:/VideoStudio/comfyUI/install/ComfyUI/ComfyUI/.venv/Scripts/python.exe
K=.claude/skills/dnf-character-patch/scripts/patch.py
```

从项目根目录运行 `$PY $K <id> <命令>`，不带参数可看全部命令。需要几分钟以上的命令放后台运行。

## 流程

### 1. 摸清职业

```
$PY $K survey swordman atequipment
$PY $K init gpt_dragon_slayer swordman atequipment sg --weapon=katana --stem=A_GPTDragon_FSlayer
```

`survey` 给出主骨架帧数、其他骨架和武器种类。路径里 `gunner/atequipment`、`mage/equipment`、`priest/atequipment`、`swordman/atequipment` 是女性职业。其他骨架（如女鬼剑的 222 帧）留在包外，保持官方外观，否则会变透明。

`init` 生成的 `patch.json` 只是初稿，字段见 [references/patch_json.md](references/patch_json.md)。

新项目还要登记到 `design/projects.json`，工作台首页才会列出它：写项目名（如“女鬼剑改 GPT 龙娘”）、`designs`（这个项目所有版本的配置目录）、`current`（当前配置）和 `npk`（NPK 名前缀）。重做形象另建配置目录时，把新目录加进 `designs` 并改 `current`。进度、版本、安装状态和花费都由工作台从文件里读出来，不用手写。只有不在人物 journal 里的花费（道具、视频）写进 `costs`。

资源库 `scripts/dnf_kb.py`（说明见 `kb/README.md`）能查全游戏的东西：`class <职业>` 列出部件、武器、特效包、切入图和已装的补丁，`draw <职业>` 给出真实的图层绘制顺序。`init` 会从资源库读出真实的 `composite_order`，并打印每层的 z 值；某一层没有 z 值时，退回原来的猜测并提示。以前看接触表猜的顺序错过：女鬼剑默认装的白色连裤袜（裤子 d 层）被压到皮肤下面，参考图和审核页里的"原版"成了光腿。龙娘、大小姐、鲸鱼娘女仆三个旧补丁按用户的决定保留旧顺序，没有改。武器图层总是画在最上面，但游戏里武器有的层在腿后面，资源库还没有武器的 z 值，判断武器的遮挡要以实机为准。职业名用 `gunner_at`（女枪手）、`swordman_at`（女鬼剑）、`mage`（女法师）这种写法。

### 2. 看原版，分段

`$PY $K <id> composites` 导出去拖影的合成帧、自动分段和接触表 `contact_all.png`。**一定要看接触表**：基础层可能很怪（女鬼剑 0000 号帽子是南瓜头），会污染所有参考图，不合适就从 `composite_order` 去掉再跑。

“去拖影”只会删衣服图层里的细条。它曾经也删鞋、皮肤和头发：腿太细时鞋和身体断开，鞋就被当成拖影丢掉，长发带也一样。女法师 15 帧因此“缺脚”，参考图少一只脚，模型就照着少画一只，用户还以为是原版缺的。**用户说原版有什么不对时，先对比全部图层，不要先信合成图。** 旧版合成图要用 `composites` 重新导出。已画好的表要先把当时的 `zoom` 写进表定义，否则切割比例会错（见 [references/prompts.md](references/prompts.md)）。

然后读懂每段动作，写 `design/<id>/clips.json`。每一帧属于且只属于一段。快动作按动作本身拆段：女枪手待机的 1-4 帧站立、5-10 帧上弹，就是两段。

**动手画之前先跑 `repeats`，列出原版重复的帧。** 一张画复用到重复帧上，写进 `design/<id>/reuse.json`（如 `{"26": 22}`，第 26 帧用第 22 帧的成品）。这样省钱，重复动作也不会一会儿大一会儿小。复用前确认两帧的握点相同，或都没有握点。像素几乎一样、握点却不同时，多半是握点算错了（女鬼剑 173 和 169 只差 9 像素，173 的握点落在刀尖上），修好握点后照样复用。

### 3. 母版

`measure` 量身材比例，写进 `master_prompt.txt`（模板见 [references/prompts.md](references/prompts.md)）。各职业的头差不多大，身高差很多，而且比例不能靠肉眼估，先量。

先确认 `standing_frames`：`init` 默认的 `[0, 3]` 只是猜的，要选接触表里手臂自然下垂的帧（女法师第 0 帧手臂是伸出去的，要用 12–13）。`measure` 和 `master-refs` 都按它算。比例从 `dev/measure.png` 的刻度上读，宽度数字里的突变可能是耳朵下缘，不一定是下巴（女法师曾因此把 0.17 误读成 0.137）。

`master-refs`、`master-draw <名字>`，再用 `small <名字>` 看缩到游戏尺寸的效果。比例不能变大头，轮廓要认得出。`small` 还会生成 `dev/grid_<名字>.png`，用它回量母版实际的比例，提示词里的数字模型不一定照做（要下巴 0.15，画成 0.172；要尾鳍 0.15，画成 0.107）。

母版要小改时用 `master-edit <新名字> <来源>`：提示词写在 `master_prompt_<新名字>.txt`，来源母版是唯一参考图，没提到的地方几乎不变（大肥鱼改肩膀和尾巴，别处变化 0.0%），比重画便宜也稳。这时不要再发三视图，否则改掉的设计会被画回去。附件在平底上时，放宽这类小调整可以本地形变，不花钱（范例 `design/fatfish_whale_maid/widen_fluke.py`）。

**还原优先。** 下游全部照母版画，母版丢的东西成品里都找不回来。标志性的大轮廓（垂袖、大翅膀、长尾、长裙）默认保留，只简化内部细节（流苏、链子、鳞片网）。不要新增参考图里没有的色块。有三视图就用三视图。

**差异表由用户确认。** 定稿前列出和参考图的差异（保留、简化、改动、去掉），连同大图和 `small` 对比发给用户。缩小或去掉设计元素是用户的决定，不是制作方的取舍。如实写清小尺寸下的代价，让用户选。女鬼剑 GPT 龙娘 v01 擅自收小翅膀尾巴、去掉垂袖、加靛蓝色块，用户看成品才发现，全部 246 帧白画。

浅色或低饱和的角色还要设 `grade`、`ink` 和 `sheet_style`，默认值会把颜色推浓。深色服装（深蓝、黑）保持默认 `grade`，白色部分偏灰时加 `clean_whites`，否则成品发灰（大肥鱼 v01 的教训）。打包前把成品和已有补丁并排放在暗背景上比一次颜色。定稿后把文件名写进 `master`。

大附件的角色先做待机和走路两张表（约 $0.4），跑完第 6 步看效果，再全部铺开。

### 4. 决定每段怎么画

| 动作 | 做法 | 原因 |
|---|---|---|
| 快动作、手部动作、持武器、走路、跑步、转身 | 动作表 | 每帧都能对上原版，手不会丢 |
| 大幅翻滚、飞踢，裙摆展开是看点 | H3 视频 | 布料连贯好看，手不重要 |
| 待机这种几乎不动的段 | 动作表一格加 `micro` 微动，数值用 `moving` 从原版量 | 同一张画不闪，不动的地方像素完全不变 |

待机不要用 `phase`。它让全身一起摆，幅度也是固定的，用户看成“正在扭曲”。先用 `moving 14-17` 看原版哪里在动、动多少：女法师战斗待机只有手臂、手和几缕头发动 1 像素，下半身完全不动，照着做就对了。身体摆动类的待机难模仿：女法师站立照原版让头和裙摆反向各摆 1 像素，用户还是觉得不好。只动尾巴、发梢、呆毛，用户又觉得太严肃。这种就重新设计：站姿本身要放松（用 `master-edit` 式的局部修改，比如把手放到身前），脚不动，身体从脚底起朝同一方向轻摇，再加呼吸，尾巴和头发错开节拍。目的是不显得静止，也不能僵。写法见 [references/prompts.md](references/prompts.md)。

原版只有手、头或头发在动、身体完全不动的几帧（女鬼剑待机抬手：手抬起、五指握拳，腿从待机第 1 帧起就没动过），不能用几张不同的画拼，整个人都会换。做法：以一帧的成品画为底，复制几份交给模型，只改手和头（一次修改调用）；本地按腿对齐后，只把上半身和变化的手贴回底图，再放进一张标 `"hold": true` 的表，表里所有帧共用一个位置，腿逐像素不变。范例 `design/gpt_dragon_slayer_v03/idle_hand_edit.py`。复核：`moving` 的下半身各行变化应为 0。

一张表里只想改一格时，把整张表当唯一参考图发给模型，提示词写明只改哪个人物。这样布局和比例都不变，可以用旧表的 `zoom` 直接切，别处变化也很小（大肥鱼改双手，头 0.0%，腿和鞋 0.1%）。

走路这类头和躯干稳定、只有手脚在动的段，在 `clips.json` 写 `"anchor": "head"`，否则按脚底对齐会把头顶来顶去。大肥鱼走路的头比原版高了 4–5 像素，这样改之后逐帧一致，不用重画。跑步也是一样（用户：“原版的头部、躯干在整个跑步过程中位置是相对不变的”）。头对齐默认只看最上面 24 行，头顶是角或飘起的头发时对不准，在段里加 `"anchor_px": 48` 把脸也算进去（龙娘跑步）。头对上后脚悬空，说明那几格画小了或腿画短了：先用 `frame_scales.json` 放大，剩下的差距用 `micro` 的 `lift` 只拉伸腰以下几像素。

默认全用动作表，不用 H3。GPT 龙娘 246 帧全用动作表，翻转段的效果也够好；Claude 大小姐 v02 因为先做了 H3 才留下一部分。动作表每张约 8 格，246 帧约 31 张、$7–8。表的格式和提示词写法见 [references/prompts.md](references/prompts.md)。

```
$PY $K <id> sheet-refs <表名>    # 先看参考图和 poses_<表名>_marked.png
$PY $K <id> sheet-draw <表名>    # 付费，看结果后再切。重画用 --version=2
$PY $K <id> sheet-cut <表名>
$PY $K <id> sheets-draw --budget=9   # 批量画所有没画过的表，到预算自动停，可重复运行。不要并行开多个 sheet-draw，会写坏 journal.json
$PY $K <id> sheets-cut               # 每张表切最新版，修复表最后切，再应用 clip_scales.json
```

一张表只有一个缩放，个别段可能和邻段大小不同。把目标身高比写进 `design/<id>/clip_scales.json`（如 `{"clip_100_102": 1.02}`），之后切表都会生效，不必另写脚本。单帧大小不对（修复表画得大小不同、一张表里某一行画小了）写 `design/<id>/frame_scales.json`（如 `{"155": 1.07}`），系数取 `sizes` 给的值；可重复运行，不会叠乘。所在段已经被 `clip_scales.json` 放大过的帧别再乘。重画单帧不要拆段，用带 `replace` 的修复表。只有要改这一段的大小时才拆：一个段只有一个目标，混了两张表的帧就会一大一小（`sizes` 会列出来）。

大小用 `sizes` 判断，它按人物面积比较各表。身高比会骗人：模型把举起的手臂画低时，人物看着变矮，整张表就被放大了（大肥鱼 8 张表因此差到 ±15%）。超过约 6% 的表按它给的系数写 `clip_scales.json`，目标值是刚切出来时的身高比乘系数，不要在已缩放的结果上再乘。`ref_cells` 也别选手臂高举的格子。

H3 只在动作表明显不够时用：`video-gen`（本地，约 5.5 分钟一段，需约 18.4 GiB 可用提交内存，可续跑），再 `video-pick <clip>`，然后 `unfreeze`。段内帧数变动时用 `split`。

### 5. 手和武器

先在**没画之前**检查原版握持点：`$PY $K <id> hands targets.png`。红圈应该落在手上。

持武器的表直接开 `"mark_grips": true`：参考图上会画品红圆点，并告诉模型把拳头画在点上。原版手和身体同色（黑手套、黑袖子）时，模型看不清手在哪，文字也说不准。GPT 龙娘 v02 第一轮有 28 帧手和刀对不上，加圆点重画后都接上了。圆点落错地方时（比如落在头发上）先写手动握点 `grip`，发图前先看 `_marked` 图。手和刀差太多时，拉手臂只能救 15px 以内，别的都要重画。

- 手枪类贴着露出的皮肤，用 `"hand_detect": "visible_skin"`。
- 刀剑类、戴手套的职业，用 `"arm_end"`，只认武器两端和细的肢体。
- 戴手套的持刀职业，手被衣服层盖住，只认皮肤会漏帧（女鬼剑 240 帧漏了 102 帧）。开 `grip_fallback` 和 `grip_gap`：武器图层的刀柄和护手之间留着缺口（原版手套遮住的部分），那里才是握点。`init` 会给长武器打开它们。
- 零星误判写进 `design/<id>/hand_overrides.json`：`{"ignore": {"138": [0]}}` 去掉假手；`{"64": [[218, 231]]}` 手动指定她的手；`{"grip": {"64": [218, 231]}}` 手动指定握点。
- `graft_hands` 只在原版手和新角色肤色接近时才合适，否则会贴上别人颜色的手。长武器 `init` 默认关闭。
- **持武器的角色，切表前必做：** 量母版上手的 RGB，设好 `skin_rule`。默认规则要求红减绿至少 36，肤色淡的角色完全认不出手。大肥鱼 62 帧握杖帧里只认出 6 帧，手和法杖都有缝；改了规则，不用重画就接上了大部分。配淡紫阴影时加 `blue_below_green`。`final` 最后会统计手的贴合方式，出现 WARNING 就是这个问题。
- 武器背在身后也可能碰巧挨着手，会被误判成握点，把拳头画错地方。写提示词前对照 `sheet-refs` 的标记图，假的写进 `ignore`（女法师 45、78、87、133、134、138–143）。
- 圆点也可能落在别的身体部位上：脚挡住手时，握点会落在脚上，模型就把脚画成拳头（女法师 92、93）。这种帧把握点写进 `ignore`，提示词写明手被脚挡住。
- 刀身横过大腿、头或身体时，握点常落在刀身和身体的交叉处，真正的手在远处的刀柄（女鬼剑 73、131、138、173、226 都是这样，173 还落在了刀尖拖光上）。每张表的 `_marked` 图里，凡是落在大腿、脚、头、刀尖或离身体很远的圆点，都要叠上武器图层核对。刀柄的位置用武器图层里的深色像素找：刀柄和护手之间的缺口就是握点，写进 `grip`。同一把刀位置不变的相邻帧可以直接用同一个握点。
- 双持职业设 `"grips_per_frame": 2`。

### 6. 合成

```
$PY $K <id> check
$PY $K <id> final
$PY $K <id> match-sizes    # 有 H3 段时：缩放后再跑一次 final
```

`final` 对全部段统一调色板、对齐脚底，最后做手部贴合。约半分钟，可随时重跑。最后两行列出拉伸过大和手太远的帧，都要放大看。原版的刀有时本来就和手分开（快动作），先和原版比再判断。

### 7. 自查，然后才给用户看

按 [references/acceptance.md](references/acceptance.md) 逐项检查。工具：

```
$PY $K <id> board all.png 0-40 12      # 上原版下新版，都带武器
$PY $K <id> hands closeup.png 6-35     # 每只手的特写
$PY $K <id> grips grips.png 13-22      # 腰部放大，红圈是握点，少量帧看得最清楚
$PY $K <id> anim walk.gif 13-22        # 动图，看布料跳动和大小突变
$PY $K <id> stats                      # 身高比、脚底、完全相同的帧
$PY $K <id> sizes                      # 各表按面积比大小，找缩放错的表
$PY $K <id> repeats                    # 原版完全重复和只差一点的帧，可以复用
$PY $K <id> moving 14-17               # 这几帧里原版哪里在动：按高度和图层统计
$PY $K <id> colors                     # 参考图、母版、成品的色相对比
```

用户验收非常细（见清单），这里查出的问题不要留给用户。

自查后请用户在工作台里逐个动作过一轮。工作台用 `preview_start` 启动 `.claude/launch.json` 里的 `workbench`（端口 8800），一个服务管所有补丁，不要再为每个补丁开端口。设计见 `docs/workbench_design.md`。

- 左边是项目、资产（人物动作、切入图、大招人物帧、武器和机器人、发光层）和单元列表；中间原版和新版同步播放，可以逐帧、叠加、调速、开关武器；右边是这个单元的问题。
- 用户在新版画面上点击落标记，提交问题。问题存在 `design/<id>/workbench/issues.jsonl`，只追加，不会被覆盖。
- 人物动作按 `clips.json` 的 `action` 分组；一个动作拆到几张表时，给这些段写同一个 `action`。人物以外的资产不用登记：工作台读项目最新的 NPK，按统一分类（转职附加外观、武器、切入图、大招人物帧、技能特效和道具、召唤物，见 `scripts/workbench/categories.py`）自动列出，每个 IMG 都和资源库查到的官方 IMG 对比。`design/<id>/workbench/assets.json` 只用来给 IMG 起分组名（范例 `design/claude_gunner/workbench/assets.json`，把 IMG 按“喷火器”“G-1 科罗纳”分组）。首页的“替换范围”表按同样的分类，一眼看出哪个项目改了切入图、哪个没改。

修问题的流程：

```
$PY $K <id> issues                     # 待修和被退回的问题，帧号同时给工具编号和用户编号，标记给出坐标
$PY $K <id> issue-fix <n> "做法"        # 修完、重跑 final 之后再写；记录当时的帧版本
$PY $K <id> issue-note <n> "说明"       # 只说明、不算修完（比如需要用户决定）
```

用户点“刷新”就能看到新帧，然后点“复核通过”或“退回”。一个动作通过之后帧又改了，会自动变成“需复核”。旧的 `review-page` 和 `review.json` 不再使用；`python scripts/workbench/issues.py <id> import-review` 可以把旧记录导入问题单。

### 8. 打包安装

`$PY $K <id> build` 生成 NPK（含回读校验）、四栏对照页和压缩包。写 `docs/<out>.md`（`out` 是 `patch.json` 里的产物目录名），再跑一次 `build` 把文档打进压缩包，然后 `install`，它会把同名旧版移出游戏目录。

升版本有两种做法。只修几帧：改 `version` 和 `out`，把旧版的 `clips/`、`parts/` 复制到新目录。重做形象：另建 `design/<id>_v02/`，复制 `patch.json` 后改 `version`、`out` 和 `npk_stem` 不变，旧版配置和产物都不动。两种做法旧版都能回退。

汇报要包含：是否实机验证、已知不足、费用、卸载方法（退出游戏后移走这一个文件）、对照页链接。

## 按当前穿戴出小补丁

整体替换补丁会覆盖一个职业的全部时装（龙娘约一万个 IMG）。只想让自己的角色变样时，用工作台试衣间的“按当前穿戴导出补丁”：把游戏里实际穿的几件设为当前穿戴，叠加项目补丁作为目标外观，再导出。得到的 NPK 只写当前穿戴的那几件 IMG，大小约 1MB，导出时会自动和目标逐帧比对。代码在 `scripts/workbench/studio.py` 的 `export_outfit`。不负责安装，放进 ImagePacks2 的事照常先问用户。

## 技能道具、大招人物帧、切入图和特效

找技能的特效文件先用工作台的“DNF 资源”页（`/#/game/<职业目录>`）：每个特效目录的原版和各项目改版并排播放。中文技能名存在 `kb/curated/skill_names.json`，确认过的名字在页面上勾“已核实”，推断的名字不要当事实用。

人物补丁之后的进阶内容，并进同一个 NPK。范例是女枪手 v03～v05，详细做法见 [references/effects.md](references/effects.md)，动手前先读。

| 内容 | 做法 | 模型 |
|---|---|---|
| 武器、道具、机器人、小件 | 动作表重画，每种物件先出设计图 | `gpt-image-2`（$0.038） |
| 官方人物帧（`awakebody_*`） | 动作表重画，先出设计图 | 2.6 native，人物不用便宜模型 |
| 冷色发光层 | 程序调色 | 不花钱 |
| 三觉切入图（全屏连续镜头） | **视频模型。不要用生图拼帧**，用户实测 v05 只有这几个有问题 | Grok 1.5 首帧视频，1080p 约 $0.52 一秒（`scripts/gunner_cutin_video.py`），v06 未实机 |
| 其余切入图（横条、斜带） | 关键帧加官方遮罩 | 2.6 native |

必须知道的几件事：

- `Script.pvf` 加密，只能换像素，时序、位置和混合方式都改不了。
- 特效 IMG 多是 V5，读取要用 `scripts/survey_gunner_effects.py` 的 `V5` 类。写回用 V2，大图占内存多。
- 没有 `at` 版本的文件男女可能共用，改了可能影响另一性别，要告诉用户。
- 实色道具不要自动换色，会发脏，要重画。14px 的 logo 看不清，要 20px 以上。
- 静态帧板看不出动画问题。全屏动画的结论要用户实机看过才算。
- 用官方标志时写明仅自用。

## 收到修改意见时

用户说的帧号从 1 开始，工具里从 0 开始，先对上再改。问题单里的 `frames` 和标记是工具编号，意见文字里的帧号是用户的编号；`issues` 命令会把两种编号都列出来。用户在聊天里提的意见，也用 `issue-note` 记到对应的问题上，免得只留在聊天里。多数问题在 [references/acceptance.md](references/acceptance.md) 里有现成做法。改完重跑 `final`，同一段相似的问题一起修，并复核相邻帧大小有没有跳变。
