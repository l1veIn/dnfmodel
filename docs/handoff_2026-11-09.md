## 用户想要什么

- 一个“成熟的工作台”，以 DNF Avatar Studio（薛定谔的化裁间，github.com/PhysicalWorldDo/DNF-Avatar-Studio）为参照：能同时看角色、技能特效、武器；能调色甚至改像素；保存搭配、对比；按“当前穿戴”导出补丁。
- 项目要有名字（“女鬼剑改龙娘”），进项目能看进度、导出 NPK。
- 对照方式要统一，一眼看出哪个项目改了切入图、哪个没改。
- 能浏览 DNF 的信息：职业、技能特效、立绘，原版和改版并排，没改过就显示“暂无改版”。
- 只自用，不开源不商用；用户同意借用 Avatar Studio 的 `avatar_data.dll`。

## 已知问题和坑

1. **武器遮挡**：patch kit 的 `armed()`（审核台、对照页用它）总把武器画在最上面。Avatar Studio 目录里有武器分层深度：左轮 b 层 650 在身后、c 层 2790 在身前；太刀 b 层 650、挥砍层 x 1350、a 层 2050。应该按 `as_layer` 的 z 值把武器插进人物图层之间。龙娘挡刀问题（#3）也要靠这个，外加把武器图层打进补丁（太刀约 644 个文件、32MB，需用户决定）。
2. **三个旧补丁的 `composite_order`** 仍是以前猜的顺序（用户决定只改以后的 `init`）。女鬼剑参考图因此缺了白色连裤袜。
3. **审核台**：有一次地址栏的分类参数和实际显示的分类对不上（`a=cutin` 却显示转职附加外观），还没查。
4. **Avatar Studio 目录**：约一半物品名为“未知单件”；部分职业默认装缺脸部、胸部、腰带（代码不是 0000）。
5. **按当前穿戴导出**：没实机验证过。被置空、被写入的是那几件时装的 IMG 路径，别人穿同样的时装、同样的配色也会受影响。身体（默认皮肤）也被置空。
6. **加 buff 视频**：官方文件是 Neople 加密的 Bink 2；社区补丁用普通 Bink 1（带透明，470×668，15 帧/秒，19 帧），游戏能播放。自制要用 RAD Video Tools 编码，**需用户同意后再下载**。覆盖 `Video` 目录前要先备份并问用户。每次游戏更新都会还原。
7. **技能中文名**：COLG 索引没覆盖的特效目录（女枪手所在的 gunner 目录还有 41 个）只有英文名，可在资源页填写（存 `kb/curated/skill_names.json`）。

### 操作上的坑

- Python 用 ComfyUI 的环境：`D:/VideoStudio/comfyUI/install/ComfyUI/ComfyUI/.venv/Scripts/python.exe`（有 PIL、numpy、scipy、av）。
- Windows 控制台按 GBK 显示，Python 打印的中文会乱码。要看中文就写到文件里，再用 Read 读；数据本身没坏。
- 改了工作台的 Python 代码要重启服务，还要结束旧的渲染进程（`worker.py`，空闲一小时才会自己退出）。PowerShell：`Get-CimInstance Win32_Process -Filter "Name='python.exe'" | ? CommandLine -like '*workbench*' | % { Stop-Process -Id $_.ProcessId -Force }`。
- `avatar_data.dll` 默认去运行程序（python.exe）所在目录找数据，`scripts/avatar_data.py` 已经设了环境变量 `DNF_AVATAR_DATA_DLL` 指向 `tools/downloads/dnf_avatar_studio_1.8.1/`。
- 资源库的导入顺序：先 `scan`，再 `avatar_data.py export`（数据有变时才需要），再 `dnf_kb.py import`。
- COLG 搜索连续两次就会被限流（“提示信息”页），要间隔开。COLG 需要登录，用户已在内置浏览器里登录；curl 访问会被拒绝。
- 用户常把下载放在项目根目录。`.gitignore` 已排除 `*.zip`、`*.downloading`、`*.baiduyun.*`，`git add -A` 前仍要看一眼 `git status`。
- 用 Python 的 `Path.write_text` 改文件会把换行变成 CRLF，不影响运行。通过 heredoc 生成的 Python 代码里，`b"\0"` 曾变成一个真正的 NUL 字节，导致文件编译失败。含转义字符的代码要用 Edit 工具或单独的脚本文件写，不要嵌在 heredoc 字符串里。
