# “dnf刃”补丁结构检查

检查日期：2026-10-22。来源：工作区 `dnf刃/`，仅离线解析；未安装补丁，未运行下载目录内的程序。索引、图像和透明性结论来自实际 NPK 字节与逐帧 IMG 解码。

## 可直接确认的结构

两个全时装版本（普通脸、阴沉脸）结构一致，各有 16,334 个资源路径条目、9 段物理数据。普通脸版本为 4,833,349 字节，其中索引占 4,312,196 字节。许多路径共享同一段图像数据，并不是作者绘制了上万套图片。

| 用途 | 实际路径数量（不计作者自定义标签） | 做法 |
| --- | ---: | --- |
| 完整人物 | 103 个 `avatar/skin/` 路径 | 全部指向同一份 `meow/本体图层.img` 的数据 |
| 覆盖原时装 | 16,222 个 `avatar/` 部件路径 | 全部指向一份透明 IMG；包括帽子、头发、脸饰、胸部、上衣、裤子、腰带、鞋子及部分 mask 名称 |
| 隐藏鬼手等附加外观 | 7 个 `growtype/` 路径 | 透明 IMG，涉及鬼手、粉色鬼手、剑魂手臂、狂战相关手臂和部分效果 |

另有两个作者自定义条目标签，使总数成为 16,334。

普通脸的“本体图层”是 IMG V2，有 179 个帧位，179 个实存帧、177 种不同像素内容；所有帧都有可见图像。抽出的帧已经包含完整脸、头发、身体、衣服、裤子和鞋子，视觉证据见 `costume_normal/body_frames/body_contact_sheet.png`。这里的 179 是该鬼剑士补丁的帧位数，不能直接作为我们女法师的帧数。

原时装共用的隐藏 IMG 有 243 个帧位：1 个实存透明帧，242 个引用帧；逐帧解码后全部透明。7 个附加外观也全部透明。原游戏部件仍可能被请求加载，但这些路径返回的是空图。

武器包有 2,699 个条目（含一个自定义标签）：2,698 个武器路径共享一份 179 帧的 IMG V4。说明武器单独随原武器动作系统显示，没有烘焙进人物本体。

技能包和语音包独立。技能包有 396 个条目；本次解码其中 4 个 weaponcombo IMG 时遇到长度边界问题，未把它们标为成功，也未修复。时装两个版本和武器的所有独立 IMG 数据均解码成功，此技能包限制不影响上面的时装结构结论。语音包有 75 个条目，内容签名是 Ogg 音频。

## 对我们制作方式的建议

采用“整套角色替换”作为第一版：先绘制整体角色动作帧，落到选定的身体/皮肤资源，再把会重叠的旧时装资源处理为透明。整体图的生成更容易保持脸型、比例、服装和光影一致，不需要为了游戏支持部件换装，就让生图模型独立生成每件衣服。

美术源文件仍应尽量保留可编辑部分；导出时是否需要增加前后发、鲸尾、手部等层，取决于武器和动作遮挡的实际检查结果。无需预先机械拆成所有原生部件，也不能保证一张合成身体层适合所有武器与技能。

若目标改为可自由混搭的独立头发、衣服、鞋子或保留原生单件染色，再走按部件拆层的路线。那需要逐部件动作序列、遮挡关系、坐标和染色/遮罩适配；不能仅裁切几张完整图就得到完整换装资源。

整体方案仍是“一帧一张完整人物”，不是一张站姿覆盖所有动作。我们已有女法师基础资源 174 个帧位，需保持女法师自己的帧序、坐标、动作和握持位置，转职附加资源另外核对。前一批 12 张的比例和姿势误差仍需修正，改变封装方式不会解决这些问题。

全时装覆盖的范围取决于路径清单。该包日期为 2024 年，不能据名称保证覆盖当前客户端的所有新增装扮。资源替换也不按角色账号识别：本地看到的其他角色若使用同一路径，同样会受影响。我们的第一版可先限定到选定资源，测试通过后再决定覆盖范围。

## 证据与复现

- `summary.json`：所有包的摘要。
- `costume_normal/report.json` / `costume_gloomy/report.json`：SHA-256、目录计数、共享偏移、帧数、透明检查。
- 各子目录的 `index.csv`：完整路径与数据偏移对应关系。
- `costume_normal/body_frames/`：12 个原始解码帧、逐帧坐标元数据和展示总览。
- `scripts/inspect_blade_patch.py`：离线检查程序。作者自定义中文标签按 UTF-8 或 GB18030 解码，官方 ASCII 资源路径保持原值。

NPK 能证明最终打包结构，不能证明作者使用了哪种绘画软件、是否用过 AI，或绘制时是否保留过分层工程。这里的建议借鉴的是封装方法，不是复用刃的角色画稿。
